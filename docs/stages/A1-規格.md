# A1 開機自動啟動 Yuki、BreezyVoice、LM Studio、SearXNG — 規格

> 對應：`企劃.md` 階段 A1。依 `docs/決定紀錄.md`：D-15（用**啟動資料夾捷徑**）、D-16（LM Studio、SearXNG 一起自動開；Windows 維持手動登入）。
> 第一版（只有 Yuki + BreezyVoice）已在 commit 9565ee1 完成，這一版是在上面加東西。

## 目標（做完的樣子）
使用者登入 Windows 後不用動手：LM Studio Server 開好、Yuki 的模型載好；SearXNG 能搜尋；BreezyVoice 就緒；Yuki 上線。
到測試伺服器打 `/來語音`，聽到的是 BreezyVoice（台灣腔）的聲音。

## 現況（影響盤點）
| 東西 | 現在怎麼開 | 查到的事 |
|---|---|---|
| Yuki | 第一版的 `watch_yuki.ps1` | 不等任何東西就開 → 這版要改成等 LM Studio、SearXNG |
| BreezyVoice | 第一版的 `watch_breezy.ps1` | 不變 |
| LM Studio | 手動開 GUI（`F:\LMSTUDIO\LM Studio\LM Studio.exe`）、手動載模型、開 Server | 有 CLI：`%USERPROFILE%\.lmstudio\bin\lms.exe`（v0.4.26）。`lms server start`／`lms daemon up` 可以不開 GUI（llmster 背景程式）；`lms load` 可指定 context、parallel、MTP。目前 GUI 開著、Server 在 8001，但載的是 **gemma-4-26b**（不是 Yuki 的模型，應是別的工具在用）|
| Yuki 的模型 | `.env` 的 `LLM_MODEL=swift-1.5-qwen3.8-27b-uncensored-dynamic-mtp@iq4_xs`；`LMSTUDIO_BASE_URL=http://127.0.0.1:8001/v1` | 開發規格第 2 節：context 16384、MTP 開、Flash Attention 開、同時預測 1 |
| SearXNG | `docker compose -f searxng/docker-compose.yml up -d`（容器 `yuki-searxng`，`127.0.0.1:8888`，`restart: unless-stopped`） | Docker Desktop 的「登入時啟動」是關的（`AutoStart: false`），目前 Docker 沒在跑 → SearXNG 也沒在跑。只要 Docker 起來，容器會自己回來 |

不受影響：`yuki/` 的程式、`.env`、測試。

## 做法
都在 `scripts/autostart/`，沿用第一版的 `common.ps1`（log、pid 檔、重開次數上限）。捷徑（`launch.vbs`）多開兩個看顧。

### 1. `watch_lmstudio.ps1`（新）
1. 已有看顧在跑 → 結束。
2. 啟動 Server：`lms server start --port 8001 --bind 127.0.0.1`（GUI 沒開時 lms 會自己叫起 llmster 背景程式，**不開 GUI 視窗**）。等 `GET http://127.0.0.1:8001/v1/models` 回應，最多 3 分鐘。
3. 載入模型：`lms ps` 裡沒有 `.env` 的 `LLM_MODEL` → `lms load <LLM_MODEL> --identifier <LLM_MODEL> -c 16384 --parallel 1 --speculative-draft-mtp -y`。模型名稱從 `.env` 讀，不寫死。Flash Attention 沒有 CLI 參數，用 LM Studio 存的模型預設（報告寫有沒有確認到）。
4. **不卸載別的模型**、不改 LM Studio 的任何設定（含它自己的開機啟動選項）。
5. 看顧：每 60 秒查一次 `/v1/models` 有沒有 `LLM_MODEL`；Server 沒回應就重做 2，模型不見就重做 3。1 小時內重做超過 5 次就停並寫 log。
6. log：`logs/autostart.log` 標 `[lmstudio]`；lms 指令輸出附加到 `logs/lmstudio.log`。

### 2. `watch_searxng.ps1`（新）
1. 已有看顧在跑 → 結束。
2. `GET http://127.0.0.1:8888/` 有回應 → 直接進看顧。
3. 否則：Docker 沒回應（`docker info` 失敗）→ 啟動 `Docker Desktop.exe`（從安裝路徑找，例如 `%LOCALAPPDATA%\Programs\DockerDesktop\Docker Desktop.exe` 或 `%ProgramFiles%\Docker\Docker\`）；等 `docker info` 成功，最多 5 分鐘。**不改 Docker 的任何設定。**
4. `docker compose -f searxng/docker-compose.yml up -d`，等 8888 回應，最多 2 分鐘。
5. 看顧：每 60 秒查一次 8888；沒回應就重做 3～4。1 小時超過 5 次就停。
6. log 標 `[searxng]`；docker 指令輸出附加到 `logs/searxng.log`。

### 3. `watch_yuki.ps1`（改）
- 每次啟動 Yuki 前（含重開），先等：`/v1/models` 有 `LLM_MODEL` **而且** 8888 有回應。每 5 秒查一次；每 5 分鐘寫一行「still waiting for lmstudio/searxng」，**不設上限**（D-16：要等兩個都能連上）。
- 其他不變。

### 4. `start.ps1`／`stop.ps1`／`launch.vbs`
- `launch.vbs` 隱藏開四個看顧：lmstudio、searxng、breezy、yuki。
- `stop.ps1`：結束四個看顧（pid 檔）和 Yuki、BreezyVoice 子程序（同第一版）。**LM Studio Server、模型、Docker、SearXNG 容器不關**（是共用的，別的工具也在用）；README 寫要關的話自己跑 `lms server stop`／`docker compose -f searxng/docker-compose.yml down`。

### 5. 文件
- README「開機自動啟動」一節：改成四個都包含；刪掉「LM Studio 和 SearXNG 不包含在內」那句；寫 stop 不關 LM Studio／Docker。
- `CLAUDE.md` 那一行由開發 PM 改。

## 驗收
1. 單元測試、個資掃描照常過。
2. Docker 關著的狀態跑 `start.ps1`：5 分鐘內 Docker 起來、`http://127.0.0.1:8888/` 回應；Yuki 在 SearXNG 好之前不會啟動（`autostart.log` 看得到在等）。
3. LM Studio：Server 在 8001、`/v1/models` 有 `LLM_MODEL`，Yuki 隨後上線（`yuki.log` 有登入訊息）。
4. 再跑一次 `start.ps1`：四個都寫「已在跑」並結束。
5. `stop.ps1`：四個看顧和 Yuki、BreezyVoice 都結束；LM Studio Server 和 SearXNG 仍在。
6. 第一版的重開測試（結束 Yuki／BreezyVoice 子程序會被重開）仍成立。
7. 使用者執行 `install.ps1` 後重開機、**登入**、不動手，3～5 分鐘內四個都好；在**測試伺服器** `/來語音` 聽到 BreezyVoice 的聲音（`yuki.log` 沒有「改用 Edge」）。這一項要使用者配合。

## 注意
- 顯卡 32GB：Yuki 的模型約 18GB、BreezyVoice 數 GB。開機時只有 Yuki 的模型會被載入，沒問題；但如果使用者另外開了別的模型（像現在的 gemma 約 16GB），兩個加起來會放不下。看顧腳本不負責卸載別人的模型，載入失敗就寫 log。
- 只動啟動資料夾（使用者跑 `install.ps1`）。LM Studio、Docker 自己的設定都不碰。

## 不做
- 不改 `yuki/` 的程式、不改 `.env`。
- 不改 Windows 自動登入、LM Studio／Docker 的開機選項。
