# A3 語音實測中發現的問題 — 修正規格

> A3 第 1 項實測（2026-11-18 20:46～20:50，測試伺服器）發現的問題。使用者決定先修再測其他項。
> 「她不查群組紀錄就亂答綽號」屬於 A5（查不到說不知道／該查就查），不在這裡。

## 實測數字（`data/logs/ai/` 的 voice 紀錄）
| | ASR | LLM | TTS（第一段合成好） | 講完到開口 |
|---|---|---|---|---|
| 不用查的 7 句 | 0.2～0.4 秒 | 0.25～1.6 秒 | 1.7～3.9 秒 | 3.0～6.0 秒 |
| 要上網查的 2 句 | 0.2 秒 | 1.8～4.0 秒 | 3.9～6.0 秒 | 11～21 秒 |
標準 ≤ 3 秒。主要卡在 TTS。

## 1. 切句：講話中間停一下就被切成兩句
- 現況：`VOICE_SILENCE_MS=700`，停 0.7 秒就送出。「先幫我查今天的 … 臺積電一塊」被切成兩句，第一句先被回答了。
- 改法（不加長每句的等待）：同一個人的下一句在**上一句的回覆還沒開始念之前**到了，就取消還在跑的回覆（LLM／TTS），把兩句接起來當一句重新回。已經開始念的就不取消（那是插話，照原本的插話邏輯）。
  - `session.py` 的 `handle`：目前「佇列還有話就先不回」只看佇列；要加上「回覆進行中被新的一句取代」。
  - 接起來的文字：上一句 + 空格 + 新的一句；追蹤紀錄記成同一筆（或前一筆 `outcome=skipped`、`degraded: ["merged"]`）。
- `VOICE_SILENCE_MS` 預設改 900（小幅放寬，避免句中換氣就切）。

## 2. ASR 提示沒有群組成員的名字和綽號
- 現況：`session.py:_transcribe` 的提示只有**語音頻道裡的人**的顯示名稱 + `bot_name` + `VOICE_ASR_HOTWORDS`。像成員的綽號完全不在提示裡。
- 改法：提示的名字加上
  - 這個伺服器所有成員的顯示名稱（`bot.members_of(guild)` 已有，含 `name`、`global_name`）；
  - 人物檔案裡的綽號：`data/profiles/<伺服器ID>/*.md` 的「綽號」段落／行裡的名字（解析規則寫在函式註解；解析不到就算了，不能報錯）。測試伺服器用 `PROFILE_FALLBACK_GUILD` 的人物檔案（跟回覆一樣）。
  - 語音頻道裡的人排最前面，總字數上限（例如 400 字）避免提示太長拖慢 ASR。快取起來，人物檔案更新或每 10 分鐘才重算，不要每句都讀檔。
- 只放名字，不放對話（開發規格 6.0：放對話會被照抄）。

## 3. TTS 開口太慢
- 現況：`speak` 把每段**同時**丟給 BreezyVoice，但伺服器有鎖、一次只合成一段，第一段可能排在後面；第一段最長 12 字。
- 改法：
  - 第一段先單獨合成，送出後再依序送後面的（念第一段時合成第二段）。
  - 第一段上限改 8 字左右（在逗號或語氣詞切；切不到就照原本）。
  - 追蹤紀錄的 `tts` 維持「第一段合成好」的時間。
- 這只能縮短 TTS，不保證 ≤ 3 秒：BreezyVoice 合成速度約 0.8 倍音長，短句也要 1.5 秒左右。報告要寫實際數字。

## 驗收
- 單元測試：合併兩句（回覆進行中來了下一句 → 取消、合併；已開始念 → 不合併）、ASR 提示包含頻道外成員和人物檔案綽號且有上限、TTS 依序送且第一段變短。全部測試、個資掃描過。
- 實機（開發 PM 帶使用者）：重測 A3 第 1 項，看「講完到開口」和切句。
