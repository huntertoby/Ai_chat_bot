# A2 維運：AI 追蹤紀錄、出錯私訊擁有者 — 規格

> 對應：`企劃.md` 階段 A2、`開發規格.md` 6.12。

## 目標（做完的樣子）
- Yuki 每次動用 AI（文字回覆、語音回覆、背景人物檔案更新）都在本機留一行完整紀錄，事後查得到「她為什麼這樣回、卡在哪」。
- 出事時擁有者（`OWNER_USER_IDS`）會收到 Discord 私訊；同一種錯誤 30 分鐘只通知一次。

## 做法
### 1. `yuki/trace.py`（新）
- `start(kind, *, guild, channel, trigger, user_ids)` 回傳追蹤物件，用 `contextvars` 設成「目前的追蹤」，讓 `llm.py` 不用改函式參數就能記錄；`async with` 用法，**在 `finally` 寫檔**（出錯、逾時、被取消也要寫）。
- 一行 JSONL 寫到 `data/logs/ai/ai-YYYY-MM-DD.jsonl`。欄位照 6.12：`trace_id`（短 uuid）、`ts`、`kind`、`guild`、`channel`、`trigger`、`outcome`（ok／skipped／error）、`degraded`（list）、`latency_ms`（dict）、`attempts[]`（每輪 LLM：messages、tools 呼叫與結果、回應、耗時）、`final`、`error`。
- 一般 log 只多一行 `trace_id=...`，方便對照。
- `user_ids` 裡有人在 `/不要記我` 名單（`ArchiveDB.opted_out`）→ **整筆不寫**。
- 保留：啟動時和每天一次清掉超過 `TRACE_MAX_DAYS`（預設 14）的檔；總量超過 `TRACE_MAX_MB`（預設 200）就從最舊的刪起。
- 寫檔失敗只寫 warning，不能讓回覆失敗。

### 2. `yuki/alert.py`（新）
- `Alerter`：`notify(kind, where, message)`。
  - 指紋 = `kind` + `where`（錯誤類型 + 位置）；同指紋 `ALERT_DEDUPE_MIN`（預設 30）分鐘內只送一次。
  - 全部加起來每小時最多 `ALERT_MAX_PER_HOUR`（預設 10）則，超過的丟掉並寫 log。
  - 還沒連上 Discord 時先排隊，`on_ready` 後一次補發（合成一則）。
  - 送之前去掉機密：Discord token、`.env` 裡看起來像 key/token/secret 的值、`Bearer ...`、長串 base64/hex。
  - 私訊對象：`OWNER_USER_IDS` 每個人。送失敗只寫 log，不重試迴圈。
  - 訊息格式：一行說明哪裡壞了（中文、白話）、時間、`trace_id`（有的話）、例外第一行。不貼整段 traceback。
- `AlertLogHandler(logging.Handler)`：ERROR 以上的 log 轉成 `notify`（kind = logger 名稱，where = 檔名:行號）。要避免自己送私訊失敗的 log 又觸發通知（無窮迴圈）。
- **LM Studio 健康檢查**：背景每 60 秒（啟動後馬上一次）打 `GET {LMSTUDIO_BASE_URL}/models`（輕量，不佔推理佇列）；連不上就 `notify("lmstudio", ...)`。恢復時寫一行 info，不另外通知。這是為了「沒人講話時 LM Studio 掛了也會知道」。

### 3. 設定（`config.py`、`.env.example`）
`TRACE_MAX_DAYS=14`、`TRACE_MAX_MB=200`、`ALERT_DEDUPE_MIN=30`、`ALERT_MAX_PER_HOUR=10`、`ALERT_HEALTH_SEC=60`。`OWNER_USER_IDS` 空的就不送（只寫 log）。

### 4. 測試（`tests/test_trace.py`、`tests/test_alert.py`）
- trace：正常／丟例外都會寫一行；欄位齊全；opt-out 的人不寫；超過天數與容量會刪；`llm.chat_tools` 的每一輪有記到（參考 `tests/test_web.py:43-75` 的 `ScriptedLLM`）；次數用完標 `tool_budget`。
- alert：同指紋 30 分鐘內只送一次（用假時鐘）；每小時上限；連線前排隊、ready 後補發；機密被遮掉；送私訊失敗不會引發新的通知。
- 不需要網路、模型、Discord。

## 驗收
1. 單元測試、個資掃描過。
2. **LM Studio 掛掉通知**：開一個自己的 Yuki，用環境變數把 `LMSTUDIO_BASE_URL` 指到沒有服務的埠（模擬 LM Studio 掛掉；**不要真的關 LM Studio**，它是共用的）。Yuki 連上 Discord 後 5 秒內擁有者收到一則私訊；同一個 Yuki 跑滿數分鐘（健康檢查跑好幾輪）不會再收到第二則。30 分鐘不重複由單元測試保證。
3. 用正常設定開 Yuki，在**測試伺服器**由使用者叫她回一則文字、講一句語音（A3 時一起做也可以）→ `data/logs/ai/` 有 `reply` 和 `voice` 各一筆，`voice` 那筆看得到 `asr`／`llm`／`tts` 各幾毫秒。
4. 測完只結束自己開的 Yuki。

## 不做
- 插話判斷的追蹤（B2 再接）。
- 不把紀錄送到任何外部服務；不改 `.env`（使用者的 `.env` 不用加新設定，都有預設值）。
- 不重做 log 系統（一般 log 照舊寫 `logs/yuki.log`）。
