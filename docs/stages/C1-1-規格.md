# C1 第一步：表情圖鑑 — 規格

> 對應：`開發規格.md` 6.14 第 1 點。試跑期間（D-25，到 11/26）**只做圖鑑，不改 Yuki 的行為**：不動 `yuki/bot.py`、`yuki/brain.py`、`yuki/prompts.py`、`yuki/chime.py`，Yuki 不重開。
> 「回覆時用表情」「啟動時比對、補建」等試跑結束再做。

## 要做的
1. **`scripts/build_emoji_catalog.py`**（新檔，一次性工具；邏輯可放 `yuki/emoji_catalog.py` 方便測試，但 Yuki 本體不 import 它）
   - 參數：`--guild <ID>`（預設 `PROFILE_FALLBACK_GUILD`，也就是主伺服器，封存區的資料在那裡）、`--limit N`（只做前 N 張，試跑用）、`--no-llm`（只抓清單＋算次數）、`--only-missing`（已有 meaning/looks 的不重做，可以中斷後接著跑）。
   - **Discord 只用 REST，不連 gateway**：`client.login(token)` 後用 `fetch_guild`、`guild.fetch_emojis()`、`guild.fetch_stickers()`；不要 `client.start()`／`connect()`，免得跟正在跑的 Yuki 搶同一個 bot 連線。跑完 `client.close()`。
   - 欄位照 6.14 的表：`id`、`name`、`animated`、`kind`（emoji／sticker）、`uses`、`last_used`、`meaning`、`looks`、`use`（預設 true），另加 `url`（Discord CDN 圖片網址，給檢查頁用）、`samples`（用來整理 meaning 的使用次數，不存對話原文）。
   - `uses`、`last_used`：封存區（`yuki/archive.py` 的 messages 表）訊息內容裡 `<:名稱:ID>`／`<a:名稱:ID>` 依 **ID** 算（改過名也算同一張）。貼圖先略過（uses=0）。
   - `meaning`：有使用紀錄的，抽最多 15 次（新的優先、分散在不同天），每次取前後各 3 則對話，交給 LLM 整理成**一句**「什麼情況用」。prompt 描述要什麼，**不放範例句**（CLAUDE.md）。說過「不要記我」（optout 表）的人的訊息不要送進 LLM。沒有使用紀錄的 meaning 留空。
   - `looks`：用 LM Studio 的視覺能力看圖（`yuki/vision.py` 的 `fetch_image` 下載縮圖；動圖取第一格），描述一句長什麼樣子。
   - LLM 呼叫用 `yuki/llm.py`，關掉思考；**一次一個請求、每張之間停一下**（試跑中 Yuki 也在用 LM Studio，不要把她卡住）。單張失敗就留空、繼續下一張。
   - 輸出 `data/emoji/<伺服器ID>.json`（`data/` 不進 git）。重跑時保留使用者手動改過的 `use`。
2. **給使用者檢查的頁面** `data/emoji/<伺服器ID>-檢查.html`（也在 `data/`，不進 git）：照使用次數排序，每列：圖、名稱、次數、最後使用、`meaning`、`looks`。只是靜態頁、直接用瀏覽器開，不用伺服器。使用次數前 30 名標出來（驗收看這 30 個）。
3. **單元測試**（不需要 Discord、模型）：從訊息內容算次數（含動圖、同 ID 改名）、抽樣（上限、前後文、排除 optout）、重跑保留 `use`、檢查頁產生。
4. README 的指令／專案結構補一行這支腳本。

## 跑一次
- 先 `--limit 5` 試，確定沒問題再跑全部。看 `logs/yuki.log` 有人在跟 Yuki 聊天時先停下等一下（不要關 Yuki）。
- 跑完確認 Yuki 還在線（`logs/yuki.log` 沒有新錯誤）。

## 檢查
- `..\.venv\Scripts\python.exe -m pytest -q` 全過；`..\.venv\Scripts\python.exe -m scripts.check_private` 過。
- commit 裡沒有伺服器 ID、表情名稱、對話內容（名稱可能含成員名字）。
