## 做法
1. `yuki/vision.py`（新）：
   - `image_urls(message)`：從 Discord 訊息取圖片 URL——圖片附件（content_type 是 image/*，或副檔名 png/jpg/jpeg/webp/gif）和 embed 的縮圖／圖片。**只收 Discord CDN 網域**（`cdn.discordapp.com`、`media.discordapp.net`），其他網址不抓。
   - `fetch_image(url, long_side)`：下載（逾時 5 秒、大小上限例如 10MB）、用 PIL 縮到長邊 `long_side`（gif 取第一格）、轉 JPEG、回傳 data URL。失敗回 None 並寫 warning，**不讓回覆失敗**。
   - 兩個尺寸常數：`REPLY_LONG_SIDE=1280`、`GLANCE_LONG_SIDE=512`（B2 插話判斷用），可用 `.env` 覆寫。
   - 圖片只在記憶體裡，**不存檔**。
2. `ChatLine` 加 `images: list[str]`（URL，不是圖片內容）；`on_message` 填進去。
3. 回覆時（文字回覆，被叫到或注意模式）：取「觸發那則 + 最近幾則」的圖片，最新的優先，**最多 5 張**，用 1280 下載，附在**最後一則 user message** 的 content（OpenAI 格式 `[{type:text}, {type:image_url}]`）。圖片前面標一行文字說明是誰、哪一則貼的，讓模型知道圖跟誰的話對應。
   - 工具呼叫（agentic、上網）的每一輪都會帶著這些圖片，這是預期的。
   - 語音回覆不帶圖。
4. 追蹤紀錄（A2）：`attempts[].messages` 裡的圖片 data URL 換成 `"[圖片]"`，只記張數和來源訊息 ID，不要把 base64 寫進 JSONL。
5. prompt：`reply_system` 加一兩句「訊息可能附圖，圖上的字和內容也是對話的一部分」即可。照 CLAUDE.md：不放範例句。
6. 低解析度：`vision.glance_images(lines, n=3)`（最近最多 3 張、長邊 512），B2 用；這次只寫函式和單元測試。

## 驗收
1. 單元測試：URL 篩選（附件、embed、非 Discord 網域被擋）、縮圖尺寸、下載失敗回 None 不拋錯、最多 5 張且最新優先、message content 格式、追蹤紀錄不含 base64。不需要網路（用 httpx MockTransport）。
2. 全部測試、個資掃描過。
3. 實機（**測試伺服器**，開發 PM 帶使用者）：
   - 貼一張只有圖上有資訊的圖（例如 App 的連續天數、遊戲結算畫面）然後叫 Yuki 問「這是什麼」→ 她講得出圖上的重點。
   - 貼兩張圖再問「哪張比較…」→ 她分得出兩張。
   - 貼非 Discord 網址的圖片連結 → 不抓、不壞。
   - 對照 `data/logs/ai/` 的紀錄：有張數，沒有 base64。
