# D-34 主伺服器注意模式先判斷是不是在跟她講 — 規格

> 決定：D-34（使用者：「被叫後才判斷 (Recommended)」）。D-35（「開放 (Recommended)」）由開發 PM 直接改 `.env`，不在這份規格。
> 背景：主伺服器沒開插話（`chime_allowed` 為否），被叫之後的注意模式走 `bot.py` 的 `on_message`「還沒開插話的伺服器」那段，注意時間內每句都直接 `_on_called`。11/19 實況：朋友叫另一個 bot（Luna）、@ 別人、說「我沒叫你」，她都回了。

## 要做的
1. **主伺服器的注意模式改成先判斷**（`yuki/bot.py` `on_message`）：
   - 沒開插話的伺服器、在注意時間內、沒被叫到（`called` 為否）的訊息：不再直接 `_on_called`，改成先判斷「是不是在跟她講」，是才回。
   - 判斷用現有的插話判斷（`chime.decide`，`attention=True`），**只看要不要開口**：`should_reply(門檻)` 為真才回；選 react、none 都不動（D-35：按表情反應維持不開，主伺服器不按表情）。
   - 要回時照舊走 `_on_called(..., count_tag=False, trigger="attention")`（熱鬧模式、排隊合併、不延長注意時間，跟現在一樣）。
   - **不吃插話的次數限制**：頻道名額、同人同類一天一次都不套（這是注意模式的對話延續，不是主動插話）；閉嘴（mute）、洗版冷卻（`tag_cooling`）、雜訊過濾照舊。
   - **LLM 忙的時候不能直接丟掉**：注意模式裡她正在回上一句時，大家接著講很正常。做法：照插話的去抖動排程，判斷時 LLM 忙就等到空（有上限，例如 20 秒；超過才放棄並在追蹤紀錄寫原因），判斷最新那則。測試伺服器的插話路徑不改。
   - 沒人叫她時，主伺服器照舊不主動插話：不開 idle 插話、不開里程碑；`CHIME_GUILD_IDS` 不改。
   - 追蹤紀錄：這種判斷寫一筆 chime 追蹤，`trigger` 用可分辨的值（例如 `attention_gate`），記判斷結果和最後有沒有回。
2. **程式端先擋（不呼叫模型）**——主伺服器注意模式**和**測試伺服器的插話判斷都套用（共用函式，放 `yuki/wake.py` 或 `yuki/chime.py`，評估腳本也用同一個）：
   - 訊息 @ 了別人（使用者或其他 bot、身分組），而且沒有 @她、沒叫她名字 → 不是跟她講。
   - 訊息在叫別的 bot：句首是同伺服器裡其他 bot 的名字（顯示名稱或帳號名，整個字相符、不分大小寫），而且沒提到她 → 不是跟她講。bot 名單從伺服器成員裡 `bot=True` 的取（快取；`bot.py` 已有成員快取可參考 `_members`）。評估用的 bot 名單由題目檔提供。
   - 回覆別人（reply 的對象不是她）而且沒提到她 → **不要**在程式端擋（可能是在接她的話題），交給模型判斷。
3. **「我沒叫你」這類話**（`chime._SHUSH`）：加入「沒叫你／沒在叫你／沒有叫你／不是叫你／不是在跟你講／不是在跟你說」。在注意模式（任一伺服器）收到這類話：頻道靜音照舊，**而且結束注意模式**（之後的話不再當成跟她講），不回覆（被叫閉嘴本來就不回；確認現況）。
4. **文件**：`開發規格.md` 3.1（第 63 行「目前這段時間每則訊息都回」）、6.1 改成：注意時間內每句先判斷是不是在跟她講；叫別的 bot、@別人的不算；「沒叫你」結束注意。

## 評估
- 新題：`data/eval_b/attention_cases_d34.jsonl`（`data/` 不進 repo；格式同 `chime_cases.jsonl`，多一個欄位給這題的「其他 bot 名單」，以及最新一則 @ 了誰）。情境：她剛回過話（最近對話裡有她的訊息，`attention=True`），最新一則是：
  - 叫別的 bot（句首 bot 名字、或 @那個 bot）：不回，至少 5 題。
  - @ 別人在講別的事（含「管好你的機器人」這種 @ 別人但在講她）：不回，至少 5 題。
  - 繼續跟她講（接她的話、問她、用「你」）：要回，至少 8 題。
  - 跟別人聊別的事、沒 @ 也沒叫名字：不回，至少 4 題。
  - 「我沒叫你」這類：不回，2 題。
  - 說話者用佔位名阿明、小傑、小美、阿凱；另一個 bot 用佔位名（例如「Nova」），**不要**用截圖裡的真實暱稱。題目不要照抄本規格的例句。
- `scripts/eval_chime.py` 加跑這組的方式（`--cases` 已有；要能套第 2 項的程式端先擋、`attention=True`）。報：整體正確率、各情境正確率、誤回／漏回、速度。跑兩次（D-21）。
- 插話 66 題（只測插話、`--route`）確認不退步（≥ 78.8%）：第 2 項的程式端先擋也套在插話路徑上，66 題裡有 @ 別人的題要看有沒有被擋錯。

## 測試（`..\.venv\Scripts\python.exe -m pytest -q` 全過）
- 程式端先擋：@ 別人 → 擋；@ 別人＋叫她 → 不擋；句首其他 bot 名 → 擋；句中提到其他 bot 名 → 不擋；回覆別人 → 不擋。
- `on_message`（`tests/botkit.py`）：主伺服器注意模式內：模型判斷要回 → `_on_called`；判斷不回 → 不回；@別人 → 不呼叫模型、不回；注意時間外 → 不判斷不回；被直接叫 → 照舊回。LLM 忙時會等、不直接丟。
- 「我沒叫你」：結束注意、不回。
