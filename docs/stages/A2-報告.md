# A2 維運：AI 追蹤紀錄、出錯私訊 — 報告（2026-11-18）

## 結果
做好了，單元測試都過；實機「LM Studio 掛掉 → 私訊」已跑，**等使用者確認私訊有收到、而且只有一則**。語音紀錄的分段耗時留到 A3 語音實測時一起驗。

## 做了什麼
- `yuki/trace.py`：每次文字回覆、語音回覆、人物檔案抽取／合併寫一行 JSONL 到 `data/logs/ai/ai-YYYY-MM-DD.jsonl`（每輪 LLM 的 messages、工具呼叫與結果、耗時、`degraded`、錯誤）。`/不要記我` 的人參與的整筆不寫。保留 14 天、上限 200MB。
- `yuki/alert.py`：出錯私訊 `OWNER_USER_IDS`。同指紋 30 分鐘一次、每小時最多 10 則、上線前的錯誤連上後補發、送出前遮掉 token／key。ERROR 以上的 log 自動轉通知；另有 LM Studio 健康檢查（啟動後馬上一次，之後每 60 秒）。
- 通知來源：LM Studio 連不上（健康檢查和回覆失敗共用一個指紋）、BreezyVoice 退回 Edge、SearXNG 連不上、語音解密失敗（每 30 秒看一次計數）、未捕捉例外。
- 語音紀錄的 `latency_ms` 分 `asr`／`llm`／`tts`（tts = 第一句合成好的時間）。
- 新設定（都有預設值，不用改 `.env`）：`TRACE_MAX_DAYS`、`TRACE_MAX_MB`、`ALERT_DEDUPE_MIN`、`ALERT_MAX_PER_HOUR`、`ALERT_HEALTH_SEC`、`TRACE_DIR`。
- README 加「維運」一節。
- 開發 PM 抽查後改一處：暖機失敗改寫 warning（原本是 ERROR，LM Studio 沒開時會多一則私訊）。

## 已知／取捨
- `/不要記我` 判斷用「任何伺服器」的名單，比規格保守。
- 插話判斷（chime）還沒有，B2 再接。
- 「長字串」遮罩規則（32 字以上的英數）可能把很長的網址片段也遮掉，只影響私訊內容。
- 沒驗到：對方不收私訊時的行為（只會寫 warning）、語音解密失敗的實際通知。
