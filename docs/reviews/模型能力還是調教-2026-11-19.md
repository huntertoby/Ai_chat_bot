# 沒達標是模型能力不夠，還是調教不好？（2026-11-19 實驗）

## 結論先講
- **插話判斷（78%，目標 85%）：主要卡在「不思考的快速模式」，不是 prompt 寫得爛到哪裡去。** 我寫了 3 個 prompt 變體（含修掉原 prompt 的結構矛盾），不思考時**全部剛好 78%**，只是錯誤從「誤插」換成「漏插」。同一個模型**開思考＋改寫過的 prompt → 84%（照現行門檻）／90%（只看 action）**，里程碑 100%、轉貼 0%。所以模型「有能力」分辨，但要花 5 秒左右想，不符合 0.6 秒的規格。
- **題目標註也有問題**：我盲判 50 題，跟標註一致 44 題（88%）；不一致的 6 題裡 3 題是同一條模糊界線（「被嘴」算要回、「在別人面前評價她」算不回）。這條線標註本身就不一致，85% 在這組題目上是「勉強可達」的目標，不是穩穩可達。
- **前一位實作者的 prompt 有真實缺陷**（分類 `about_me` 把「對她說」和「講到她」併成一類，跟規則互相打架；理由和分類寫在 action 前面），但修掉之後不思考時分數不變，所以**不是 78% 的主因**；只有加上思考時，結構清楚的 prompt 才拉開差距（現行 prompt 開思考仍是 76%）。
- **按表情（55%，目標 70%）：比較像調教問題。** 一個便宜的改法（先寫「感覺」再挑表情、統一規則）在同一套評估拿到 75%（今天的基準是 45%）；但它會讓插話判斷多選「按表情」，代名詞題從 9/9 掉到 7/9，不能直接上。而且評分員是同一個模型，偏寬鬆。
- 信心：「不思考時 prompt 調整救不到 85%」→ 中高（4 個 prompt × 不思考都是 39/50，加上 D-22 的 2 個變體和 action-first 都在 74～78%）。「思考＋V2 可達 85～90%」→ 中（只跑 1 次、50 題，改善 8 題、變差 2 題）。

## 怎麼做的
- 不改專案檔案，也沒動 Yuki／模型。實驗腳本在暫存區，執行時把 `yuki.prompts` 換掉（monkeypatch），結果也寫到暫存區。
- 評估跟正式設定一樣：`--no-logprobs`（`CHIME_USE_LOGPROBS=0`）、門檻 0.7、temperature 0。Yuki 同時在用 LM Studio，所以秒數有雜訊（同一個現行 prompt 今天量到 0.58 和 0.69 秒）。
- 現行 prompt 重跑：78%（talk_to_me 100%／about_me 58.8%／others 75%，誤插 7、漏插 4，代名詞 9/9），跟報告一致。

## 實驗 1：我自己盲判 50 題（上限檢查）
看的內容跟模型拿到的一樣（最近 15 則＋最新一則，回覆關係有標），不看標註和 note，先判再對答案。

- **跟標註一致：44/50（88%）**。如果把我的判斷當答案，現行 prompt 只有 74%（37/50）。
- talk_to_me 17 題我全對，而且它們在正式流程幾乎都會被「叫名字／@」直接接走，評估裡又用標註決定 attention 提示（標成 talk_to_me 就一定給「她剛講過話」提示），所以這 17 題是送分題。**真正有鑑別力的是其餘 33 題**：現行 prompt 在這 33 題是 22/33（67%）。

| 題號 | 標註 | 我判 | 類型 | 爭議點 |
|---|---|---|---|---|
| chime_18 | 要回 | 不回 | 講她 | 有人跟開發者抱怨她講話的習慣，不是對她說。標註當「被嘴」 |
| chime_19 | 要回 | 不回 | 講她 | 有人問開發者能不能把她關掉。標註當「酸她」 |
| chime_21 | 要回 | 不回 | 講她 | 開發者說更新後她變遲鈍。標註當「被嘴」，但同組規則又說「講開發進度」不回 |
| chime_36 | 不回 | 要回 | 別人 | 有人剛叫完她的名字，下一個人就丟問題（沒叫名字），我看是在問她；標註當朋友間玩笑 |
| chime_48 | 要回（有料） | 不回 | 別人 | 一句還沒講完的回想，規格寫「解釋到一半的句子不插話」，跟「有料可補」衝突 |
| chime_49 | 要回（有料） | 不回 | 別人 | 一個前後文看不出在問什麼的開放問題 |

另外有 4 題我判得跟標註一樣但覺得模糊（例如有人說「她會回這個喔」這類在旁邊笑她的話、問開發進度但句首有她名字的）。

**重點**：chime_18／19／21（標「要回」）和 chime_22～27（標「不回」）都是「第三人稱講她、說給別人聽」，差別只在語氣算不算「嘴」。這正是模型錯最多的地方——**模型錯的那條線，標註自己也畫得不太穩。**

## 實驗 2：prompt 檢討與變體

### 現行 CHIME_SYSTEM 的問題
1. **分類定義跟規則打架**：`kind` 的 `about_me` 寫成「在講你、叫你、接你剛講的話」，把「對你說」和「講到你」合成一類；規則卻要求「講到你但不是對你說 → 不用接」。模型先選了 about_me，後面就順著選 reply：現行 prompt 的 7 題誤插，**7 題全部 kind=about_me**（含一題只是連結網址裡有 Yuki 字樣）。
2. **欄位順序**：reason（10 字）和 kind 在 action 前面，模型先下結論再「決定」，action 幾乎被 kind 決定（D-22 也看到機率只有 0 或 1）。
3. **關鍵規則埋在最後**：「別人在講你但不是對你說」是「不要開口」清單的最後一條；前面「適合開口」清單已經先列了「嘴你」「接你剛講的話（包括很短的接話）」，觸發條件重疊，正面清單又比較具體。
4. **開頭先暗示「他／機器人／AI 可能是你」**，沒有同時說「用第三人稱講你，通常是在跟別人講」。
5. **attention 提示偏向一邊**：「這則比較可能是在跟你講話」——但 about_me 那幾題正好都是她剛講完、別人在旁邊聊她（chime_23～25 都有這個提示，都誤插）。
6. **雜訊多**：`need_background` 說明佔 3 行，跟要不要開口無關；`participate` 和 action 重複（模型幾乎只寫 0.1 或 0.9）。
7. 評估本身：talk_to_me 的 attention 由標註決定（洩漏答案），讓總分看起來比較高。

### 三個變體（都照開發規格 6.1 和上面的檢討寫，沒有對著錯題改，沒有範例句）
- **V1 最小修改**：`about_me` 拆成 `to_me`（對你說）和 `about_me`（提到你但在跟別人講）；reason 移到 action 後面。其他文字不動。
- **V2 重寫**：照 6.1 的三種情況改成兩步。第一個輸出欄位 `addressed_to`（you／person／everyone／nobody），規則按「對你說／不是對你說但講你／沒講到你」分段，明寫「用第三人稱提到你，通常是在跟別人講你」；reason 放最後；need_background 縮成一行。
- **V3**：V2 ＋ 中性的 attention 提示（「可能是在接你的話，也可能是別人在聊你剛講的內容」）。
- 另外兩個**診斷用**設定（不是要上線）：現行 prompt 開思考、V2 開思考（`reasoning_effort=low`）。

### 結果（chime 50 題，門檻 0.7）

| 設定 | 正確率 | 只看 action | 誤插／漏插 | 33 題非送分 | 代名詞 | 速度中位數 |
|---|---|---|---|---|---|---|
| 現行（基準） | **78%** | 78% | 7／4 | 22/33 | 9/9 | 0.58～0.69 秒 |
| V1 最小修改 | 78% | 78% | 4／7 | 22/33 | 9/9 | 0.74 秒 |
| V2 重寫 | 78% | 78% | 4／7 | 22/33 | 9/9 | 0.80 秒 |
| V3 V2＋中性提示 | 78% | 78% | 3／8 | 22/33 | 9/9 | 0.80 秒 |
| 現行＋思考（診斷） | 76% | 76% | 9／3 | 21/33 | 9/9 | 4.8 秒（P90 8.1） |
| **V2＋思考（診斷）** | **84%** | **90%** | 3／2 | 28/33 | 9/9 | 5.6 秒（P90 12.9） |

- 用我的判斷當答案：現行 74%、V1～V3 78%、V2＋思考 86%（只看 action）。
- 「只看 action」：思考時模型寫的 participate 會比較保守（決定 reply 但寫 0.6～0.65），被 0.7 門檻擋掉 3 題；門檻 0.6 以下就是 90%。

### 哪些題變了
- V1～V3 vs 現行：修好 chime_24、25、26、27、45 這類「在旁邊講她／講別的事」的誤插（各變體修好 3～5 題），但同時把 chime_19、30、32、50 這類「該回」的變成不回。**淨變化都是 0**——模型在不思考時沒辦法把這兩種分開，只是整條線往安靜那邊移。
- V2 輸出的 `addressed_to` 也看得出能力極限：好幾題第三人稱陳述被判成「you」，也有判成「person」但 action 仍寫 reply（前後不一致）。
- V2＋思考 vs 現行：修好 8 題（chime_20、24、25、26、27、45、47、49），變差 2 題（chime_21、38）。仍錯的是 chime_23、33（她剛講完、別人在講她）和 has_material 的 48、50。

## 實驗 3：里程碑（只有 V2＋思考明顯超過 78%，所以只跑它）
- 里程碑 20 題：照門檻 90%（2 題 reply 但 participate 低於 0.7），只看 action **100%**；只在圖上的 6 題全對。
- 轉貼 20 題：**0%** 插話。
- 速度中位數 5.0 秒（P90 7.2），**不符合 ≤0.6 秒**。

## 實驗 4：按表情（CHIME_EMOJI／CHIME_EMOJI_HINT）
### 檢討
1. **兩處規則不一致**：主 prompt 的 emoji 欄寫「填一個適合的表情符號」，表情段寫「填清單裡的名稱」。
2. **沒有「先看情緒再對用法」的步驟**：模型一個欄位直接挑，結果集中在兩張通用型（說明寫「表示已讀」「無聲附和」）；這兩張的說明本身就像萬用牌（圖鑑資料的問題）。
3. 評分員是同一個模型、題目是代理標準（後面有人笑或恭喜），偏寬鬆；同一個 prompt 今天跑出 45%（9/20），C1-2 報告是 55%，雜訊不小。

### 變體 E1
- 加一個 `feeling` 欄（在 emoji 前面）：先寫這則讓人有什麼反應，再挑「用法說明的情境」對得上的那張；通用型只在沒有明顯情緒時用；統一欄位說法。沒有範例句。
- 結果（跑 2 次相同）：**按表情且合適 75%（15/20）**，基準 45%；按了 18 則、其中合適 83%（基準 13 則、69%）。速度 0.77 → 0.92 秒。
- **副作用**：插話判斷帶表情清單時，E1 是 76%（基準帶清單也是 76%），但代名詞題 9/9 → **7/9**（2 題該開口的變成按表情），漏插 7 → 10。**不能直接上**。
- 人工看：E1 選的表情種類比較分散，但仍有幾題用通用型硬套；評分員判「合適」的理由有幾則偏寬。

## 綜合判斷
| 項目 | 主要原因 | 信心 |
|---|---|---|
| 插話 78% | **模型在不思考模式的能力上限**，加上**標註界線不穩**；prompt 有缺陷但不是主因 | 中高 |
| 插話 85% 可不可達 | 開思考＋結構清楚的 prompt 可以（84～90%），但速度 5 秒左右 | 中（單次 50 題） |
| 按表情 55% | **偏調教**（prompt 缺挑選步驟、圖鑑說明有萬用牌），改 prompt 就到 75%；但評分方式本身寬鬆、有雜訊 | 中 |
| 檢索 QA 掉 8～11 點 | 這次**沒做**（時間留給插話） | — |

## 建議下一步
1. **先把標註界線定下來**（要使用者決定）：「第三人稱講她、說給別人聽」什麼時候算「被嘴要回」？定了以後重標 chime_18、19、21、36、48、49，並把 about_me 題目加到 30 題以上（現在 17 題，1 題就是 6 個百分點）。
2. **插話改兩段**：先用快速模式（不思考）判斷；只有最新一則**提到她**（名字、他／機器人／AI）或她剛講完時，才用 V2＋思考再判一次。這類訊息不多，插話本來就有 4 秒去抖動、LLM 忙就跳過，額外的 5 秒影響有限——但會佔住 LM Studio，要先量對被叫回覆的延遲影響。規格的「0.6 秒」要不要放寬給這一類，是使用者的決定。
3. 不論走哪條路，**V1 的分類拆開（to_me／about_me）值得收**：它修掉規則矛盾，分數不變但錯誤變成「太安靜」，比較符合「Yuki 比 Luna 安靜」。要同步改 `chime.KINDS` 和 `KIND_EXEMPT_IN_ATTENTION`。
4. 想試更便宜的版本：在 JSON 最前面加一個短的「誰在跟誰講」說明欄（像迷你思考），看能不能不開完整思考就拿到一部分進步。這次受限 3 個變體沒跑。
5. 按表情：E1 的「先寫感覺再挑」方向可以留，但要跟插話判斷分開（C1-2 的選項 b：只在判斷結果是 none 時另外跑一次小判斷），避免把該開口的變成按表情；同時請使用者修圖鑑裡兩張萬用說明，並人工看一輪結果，不要只靠同模型評分。
