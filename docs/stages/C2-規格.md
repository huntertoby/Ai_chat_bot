# C2 人物檔案：本人更正、被反駁的刪掉 — 規格

> 來源：`企劃.md` C2、`開發規格.md` 6.5。總 PM：照企劃順序做；使用者評完表情檢查頁後會插隊先處理表情。
> 現況：人物檔案兩層——`data/profiles.db` 的一條條 facts（`yuki/profile/store.py` `ProfileDB`），合併成 `data/profiles/<guild>/<user>.md`（`ProfileFiles`）；抽取／合併在 `yuki/profile/builder.py`（`extract_segment`、`merge_one`），自動更新 `yuki/profile/auto.py`，prompt 在 `yuki/profile/prompts.py`（`extract_user`、`merge_user`）。合併目前只補充，不會刪。

## 先做影響盤點（寫進報告開頭）
- 抽取和合併的流程、.md 檔的格式（有哪些區塊）、回覆時怎麼讀（`for_prompt`）、`/不要記我`（D-28 optout）怎麼處理檔案。
- 回覆 prompt 裡人物檔案的標法（6.5 第一條「你對這個人的印象（可能有錯）」）現在有沒有做到；沒有的話列出，這段一起補。

## 要做的
1. **本人更正**（6.5）：
   - 抽取時能認出「本人在更正關於自己的事」（例如否認別人講他的事、說自己已經不是那樣），存成一種新的 kind（例如 `correction`），**只認說話者就是那個人本人**（程式比對 subject_id 和發言者 ID；別人替他更正不算）。
   - 合併時寫進 .md 的「本人更正」區塊，帶日期；**優先權最高**：跟其他內容衝突時以它為準，合併 prompt 要能看到它、不能改寫或刪掉它。重建檔案（`merge` 重跑、`reset_merged`）時保留這個區塊（程式保留，不靠模型照抄）。
   - 回覆時人物檔案裡有本人更正的，放在那個人檔案的最前面。
2. **被反駁的刪掉**（6.5）：
   - 合併時模型可以**提議**刪掉舊內容（被新的、更可信的資訊反駁：本人更正、本人後來說的話、較新的事實），輸出要附理由和依據（對應哪幾條新 facts）。
   - **程式裁決**（AI 只能提議）：要刪的那條確實存在於舊檔；依據的 fact 確實在這批新 facts 裡、而且比舊內容新；本人更正區塊的不能刪；一次合併刪除數量有上限（常數）。不符合就不刪。
   - 刪掉的內容和理由記到紀錄（例如 `data/profiles/<guild>/<user>.removed.jsonl` 或追蹤紀錄），可以查、可以還原；不進 repo。
   - 梗（meme／joke）不因為「被反駁」刪掉（梗本來就不是事實，開發規格 6.7），除非是本人更正。
3. **文件**：開發規格 6.5 更新成現況。

## 評估
- **合成題**（放 `data/eval_c2/`，不進 repo）：用佔位名（阿明、小傑、小美、阿凱）造人物檔案＋新訊息片段，至少：
  - 本人更正 ≥ 8 題（含 3 題「別人替他更正」不該算、2 題本人在開玩笑／反諷不該算）；
  - 被反駁該刪 ≥ 8 題；不該刪（新資訊只是補充、或來源是別人亂講、或舊的是梗）≥ 8 題。
  - 報：本人更正抽對率、誤抽數；該刪的刪對率、不該刪的誤刪數（**誤刪是重點，要接近 0**）。各跑兩次（D-21）。
- **真實資料抽查**：拿 `data/profiles/` 現有的幾個人（複製到暫存，不改正式檔）跑一次新合併，人工看有沒有亂刪。報告只寫統計和佔位例子。
- 回覆評估：只有改到回覆 prompt 的人物檔案標法才需要；有改就跑合成 200、真實 80、閒聊 30 各兩次，跟 R3/D-37 的數字比。

## 測試（`..\.venv\Scripts\python.exe -m pytest -q` 全過）
- 本人更正：本人說 → 存；別人說 → 不存；重建檔案後區塊還在；合併 prompt 拿得到。
- 刪除裁決：依據不存在／比較舊／目標是本人更正／超過上限 → 不刪；合法 → 刪並記紀錄。
- optout 的人：不抽、不建檔（照舊）。
