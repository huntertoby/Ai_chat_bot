# R2 回覆 prompt 三個問題 — 規格

> 來源：11/19 主伺服器實況（`logs/yuki.log` 約 2783～2876 行，21:03～21:13；當時的回覆內容在追蹤紀錄 `data/logs/ai/`）。總 PM：做法類，不用等使用者決定；不放會被照抄的範例句；回覆評估重跑跟上一版比；交件附改前改後實際回覆對照。
> 上一版數字：`docs/stages/R1-報告.md`（合成 200 77.0%／78.5%、真實 80 82.5%、閒聊 30 不查 95%、回覆用表情 18～24%、兩岸 80%）。

## 三個問題
1. **開頭千篇一律**：連續 5 則都用「髒話＋對方名字」開頭。
2. **被嘴接不好**：有人 @她 嘴她沒用，她卻回頭講對方更早說的兩件事（還查了 3 次聊天紀錄），沒有回嘴。
3. **人稱搞錯**：「你可以把 @某人 當狗使喚」，她把「你」理解錯（回「下次要她幹嘛…」，把對象搞混）。

## 要做的
1. **先找原因再改**：讀 `yuki/prompts.py` 的人設與回覆規則、`yuki/brain.py` 組 messages 的方式，找出為什麼會這樣（例如人設是否鼓勵叫名字或講髒話開頭、最新訊息是怎麼標「誰對誰說」、@ 的人在文字裡變成什麼、被嘴時有沒有規則、什麼情況會去查聊天紀錄）。原因寫進報告。
2. **開頭重複**：優先用程式給的資訊而不是例句。例如：在給模型的內容裡附上她最近幾則回覆的開頭，規則寫「不要跟最近幾則用一樣的開頭方式」；或人設裡說明開頭要變化、不必每次叫對方名字。只描述怎麼做，不給要說的話。
3. **被嘴**：規則說明被嘲笑／挑釁時，直接針對那句回嘴、簡短，不要轉去聊別的事；這種情況不需要查聊天紀錄（跟 R1 加的「閒聊不用查」一致）。不放範例句。
4. **人稱**：確認 @ 別人的訊息送進模型時，「@某人」有被換成名字、模型看得出「你」是指她、「@的那個人」是第三者。需要的話在最新訊息前標出「說話者 → 對誰說」或在規則講清楚「你」通常是指你自己、@ 的名字是別人。
5. 插話判斷的 prompt（`CHIME_SYSTEM` 等）不動。

## 評估
- **針對這三個問題的小評估**（新增，資料放 `data/eval_r2/`，不進 repo）：
  - 依實況改寫成佔位名的情境，每類至少 6 題：連續被叫好幾次（看開頭有沒有重複）、被嘴（看有沒有直接回嘴、有沒有亂查）、@ 別人＋「你」（看人稱對不對）。說話者用阿明、小傑、小美、阿凱。
  - 腳本走正式的回覆流程（可參考 `scripts/eval_emoji.py` 的 reply 部分或 `scripts/eval_agentic.py` 怎麼建 brain）。
  - 開頭重複用程式算：連續 5 則裡相同開頭（前 2～3 個字，或「髒話＋名字」形式）的次數。被嘴、人稱用同一個模型評分，**另外你自己逐則看**，人工數字跟評分員並列。
  - 改前、改後各跑兩次。
- **回覆評估重跑**（各兩次，D-21）：合成 200、真實 80、閒聊 30（跑法見 `CLAUDE.md` 評估節）、`scripts/eval_emoji.py` 的回覆用表情、兩岸（`data/eval_r1/cross_strait.py`）。跟上一版比，不能明顯退步（超過兩次之間的浮動）。
