# A1 開機自動啟動 — 報告（2026-11-18）

## 結果
登入 Windows 後自動開四樣：LM Studio Server＋Yuki 的模型、Docker＋SearXNG、BreezyVoice、Yuki（等前兩樣好了才開）。腳本做好、能測的都測過。
**還差兩步要使用者做**：跑一次 `install.ps1` 把捷徑放進啟動資料夾（開發 PM 執行時被權限擋下）；然後重開機、登入，到測試伺服器 `/來語音` 驗收。

## 做了什麼（`scripts/autostart/`）
| 檔案 | 作用 |
|---|---|
| `watch_lmstudio.ps1` | `lms server start`（埠 8001，不開 GUI）；`lms ps` 沒有 Yuki 的模型就 `lms load`（context 16384、parallel 1、MTP）。每 60 秒檢查，不見就重做；1 小時超過 5 次就停。不卸載別的模型、不改 LM Studio 設定 |
| `watch_searxng.ps1` | Docker 沒開就開 Docker Desktop，等好了 `docker compose up -d`；每 60 秒檢查 8888。不改 Docker 設定 |
| `watch_breezy.ps1` | 等 WSL，開 BreezyVoice，掛掉 10 秒重開 |
| `watch_yuki.ps1` | 等「Yuki 的模型已載入」且「SearXNG 有回應」才開 Yuki（每 5 分鐘記一行還在等）；掛掉 10 秒重開 |
| `start.ps1`／`launch.vbs` | 隱藏視窗開四個看顧 |
| `stop.ps1` | 只結束看顧和它開的 Yuki、BreezyVoice；**不關** LM Studio、Docker、SearXNG（共用） |
| `install.ps1`／`uninstall.ps1` | 建立／刪除啟動資料夾捷徑 `Yuki 自動啟動.lnk` |

## 已知限制／要注意
- **Docker Desktop 開的時候會跳出它的主視窗**（它自己不理「隱藏」）。要不跳只能改 Docker 自己的設定，沒有碰。
- **顯卡**：Yuki 的模型約 17～18GB。若登入後有別的工具先載了大模型（像 gemma 16GB），Yuki 的模型會載不進去，看顧重試 5 次後停下並寫 log，Yuki 會一直等。
- Flash Attention 沒有 CLI 參數，用 LM Studio 對這個模型存的預設；無法用腳本確認。
- 「模型已載入」用 `lms ps` 判斷（這台的 `/v1/models` 會列出所有下載過的模型，不能用）。
- Docker Desktop 用 WMI 啟動，這樣 `stop.ps1` 結束看顧時不會連帶把 Docker 殺掉。
- 只在**登入後**才跑（D-16：維持手動登入）。
- BreezyVoice 看顧每次啟動前會清掉 WSL 裡殘留的 `breezy_server.py`。

## 使用者要做的
1. 跑一次（用完整路徑，在哪個資料夾跑都可以）：`powershell -ExecutionPolicy Bypass -File F:\PythonProject\Ai_chat_bot\Ai_chat_bot\scripts\autostart\install.ps1`
2. 重開機、登入，等 3～5 分鐘（Docker 視窗會跳出來，可以關掉或縮小——關掉視窗 Docker 仍在背景跑）。
3. 到測試伺服器 `/來語音`，聽是不是 BreezyVoice 的聲音；有問題看 `logs/autostart.log`。
