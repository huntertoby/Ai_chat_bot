# A1 開機自動啟動 Yuki 和 BreezyVoice — 規格

> 對應：`企劃.md` 階段 A1。啟動方式依 `docs/決定紀錄.md` D-15：**啟動資料夾捷徑**（不用工作排程器）。

## 目標（做完的樣子）
電腦重開、使用者登入 Windows 後不用動手，Yuki 上線；到測試伺服器打 `/來語音`，聽到的是 BreezyVoice（台灣腔）的聲音，不是 Edge。

## 現況（影響盤點）
| 東西 | 現在怎麼開 | 位置 |
|---|---|---|
| Yuki | 手動：`..\.venv\Scripts\python.exe -u main.py >> logs/yuki.log 2>&1` | `main.py` → `yuki/bot.py:run()`；掛掉就停，沒人重開 |
| BreezyVoice | 手動進 WSL：`cd ~/BreezyVoice && . .venv/bin/activate && PYTHONUTF8=1 python /mnt/f/.../scripts/breezy_server.py` | 埠 8890，`GET /health` 可檢查 |
| WSL | 預設發行版 `swift`（另有 `docker-desktop`）；沒有程序在跑時會自己停 | — |
| Yuki 怎麼接 BreezyVoice | `.env` 的 `VOICE_TTS=breezy`、`VOICE_TTS_URL=http://127.0.0.1:8890`；BreezyVoice 沒開時 `yuki/voice/tts.py` 的 `BreezyTTS` 會改用 Edge | 所以 BreezyVoice 沒起來時「有聲音但不是她的聲音」，驗收要聽 log 有沒有「改用 Edge」 |

不受影響：Yuki 的 Python 程式、`.env`、測試。這一項只新增啟動腳本和文件，不改 `yuki/`。
不在範圍（但會影響驗收）：LM Studio（埠 8001）、SearXNG（Docker）自己開機啟動 —— 見「待確認」。

## 做法
啟動資料夾捷徑沒有「失敗重試」，所以**看顧（掛掉重開）全在腳本裡做**。新增資料夾 `scripts/autostart/`：

### 1. `watch_breezy.ps1` — 啟動並看顧 BreezyVoice
1. 已有服務在 8890 回應 `/health` → 寫 log 後結束（使用者自己開的就不碰）。
2. 等 WSL 能用：重複 `wsl.exe -d <發行版> -e true`，每 5 秒一次，最多 3 分鐘；逾時寫 log、結束。
3. 啟動：`wsl.exe -d <發行版> -- bash -lc "cd ~/BreezyVoice && . .venv/bin/activate && PYTHONUTF8=1 exec python <專案的 /mnt 路徑>/scripts/breezy_server.py"`，stdout/stderr 附加到 `logs/breezy.log`。
   - 發行版（預設 `swift`）放腳本最上面當參數；專案的 `/mnt/f/...` 路徑從腳本所在位置推出來，不寫死。
4. 看顧迴圈：程序結束就等 10 秒再開；**1 小時內重開超過 5 次就停**並寫 log（壞掉時不要無限重開吃 GPU）。
5. 這個 `wsl.exe` 一直活著，WSL 就不會自己停掉。

### 2. `watch_yuki.ps1` — 啟動並看顧 Yuki
1. 已有 Yuki 在跑（命令列含本專案 `main.py` 的 python 程序）→ 寫 log 後結束，不重複開、不碰使用者的。
2. 啟動：`..\.venv\Scripts\python.exe -u main.py`，工作目錄 = 專案，輸出附加到 `logs/yuki.log`。
3. 不等 BreezyVoice（Yuki 要說話時才叫 TTS）。
4. 看顧迴圈：同上（10 秒後重開；1 小時超過 5 次就停）。退出碼 0 也重開（Yuki 不會自己正常結束）。

### 3. 共通
- 看顧本身的紀錄寫 `logs/autostart.log`，每行有時間和 `[yuki]`／`[breezy]`。
- 每個看顧腳本把「自己的 PID」和「它開的子程序 PID」寫到 `logs/autostart/<yuki|breezy>.pid`，給 stop 用。
- **同一時間只能有一個看顧**：開始時若 pid 檔裡的看顧程序還活著 → 結束（避免重複點捷徑開兩份）。
- 不跳黑窗：捷徑用 `wscript.exe` 跑一個小 `.vbs`（或 `conhost.exe --headless`，實作者擇一），以隱藏視窗啟動兩個看顧腳本；`powershell.exe -NoProfile -ExecutionPolicy Bypass`。報告寫用了哪個、有沒有閃窗。

### 4. `start.ps1`／`stop.ps1`／`install.ps1`／`uninstall.ps1`
- `start.ps1`：以隱藏視窗各開一個 `watch_breezy.ps1` 和 `watch_yuki.ps1` 後立即結束（捷徑指向它或它的 .vbs 包裝）。
- `stop.ps1`：讀 pid 檔，先結束看顧程序、再結束它開的子程序（Yuki python、wsl.exe 那支 BreezyVoice）。**只結束 pid 檔裡記的程序**，不靠名字亂殺；結束 wsl.exe 後若 8890 還在回應，再用 `wsl.exe -d <發行版> -- pkill -f breezy_server.py` 收尾。
- `install.ps1`：在目前使用者的啟動資料夾（`[Environment]::GetFolderPath('Startup')`）建捷徑 `Yuki 自動啟動.lnk`，指向上面的啟動方式；工作目錄 = 專案。可重跑（覆蓋）。
- `uninstall.ps1`：只刪這個捷徑。
- 只動啟動資料夾，**不改任何其他系統設定**（不碰工作排程器、登錄檔、電源、自動登入）。

### 5. 文件
- `README.md` 安裝節加「開機自動啟動」一小段：install／uninstall、手動 start／stop、log 在哪。
- `CLAUDE.md` 環境節加一行：自動啟動腳本在 `scripts/autostart/`；開機自動開的 Yuki 也算使用者的，開發要自己開 Yuki 前先 `stop.ps1`、測完再 `start.ps1` 還原。（CLAUDE.md 由開發 PM 改，不給實作者。）

## 驗收
1. 單元測試、個資掃描照常過。
2. 手動 `start.ps1`（WSL 停著的狀態）：不跳黑窗；3 分鐘內 Yuki 上線（`logs/yuki.log` 有登入訊息）、`GET 127.0.0.1:8890/health` 回 OK。
3. 再跑一次 `start.ps1`：兩個都寫「已在跑」並結束，不會開出第二份。
4. 結束 Yuki 的 python 子程序（pid 檔記的那個）→ 約 10 秒後被重開；BreezyVoice 同樣測一次。
5. `stop.ps1` 後：pid 檔裡的程序都沒了、8890 不再回應。
6. `install.ps1` 後啟動資料夾有捷徑；雙擊捷徑效果同 2。
7. 重開機、登入、不動手 → 2 的結果成立；在**測試伺服器** `/來語音` 聽到 BreezyVoice 的聲音（log 沒有「改用 Edge」）。重開機需要使用者配合。
