# D-34 報告（草稿）：主伺服器注意模式先判斷是不是在跟她講

## 結論
- 主伺服器（沒開插話）被叫之後的注意模式，**不再每句都回**。沒叫她的每句話，先用插話判斷（`attention=True`）看是不是在跟她講，模型選「回覆」而且過門檻才回。選按表情或不動，都不回也不按。
- **程式端先擋**（不呼叫模型）：@ 了別人、句首叫同伺服器的其他 bot，而且沒提到她。主伺服器注意模式和測試伺服器的插話判斷用同一個函式（`yuki/wake.py` `addressed_elsewhere`），評估腳本也用它。
- 「沒叫你／不是在跟你講」這類話加進 `chime._SHUSH`。在注意模式內（她被叫過或剛插話），沒直接叫她的人講這類話：頻道照舊靜音，**注意模式也結束**，不回。

## 程式端先擋的邊界
擋下（不呼叫模型，追蹤紀錄寫 `skipped:at_other` 或 `skipped:other_bot`）：
- **@ 了別人**：內文真的有 `<@ID>` 或 `<@!ID>` 的使用者（人或其他 bot），或任何身分組 tag（`role_mentions`），而且沒 @她、內文沒有她的名字。
  - Discord 回覆時自動 ping 被回覆的人（內文沒有 `<@ID>`）**不算**，所以回覆別人的訊息會交給模型判斷。
  - `@everyone`／`@here` 不算 @ 別人（不擋）。
- **句首叫別的 bot**：比對規則跟 `direct_call` 判斷句首一樣，前面只能有空白、標點、@、短招呼語；接著是同伺服器其他 bot 的顯示名稱、帳號名或 global_name（英數字的名字要整個字相符，不分大小寫）；而且整則沒有她的名字。名字後面接什麼都算（不像叫她時要接標點或「你」）。
  - 句中提到別的 bot、名字只是前綴（像「Novak」）都不擋。

不擋：
- 回覆別人的訊息。
- @ 別人但也叫了她的名字。主伺服器有名字就算叫她（D-32 照舊），直接回。

被擋下的訊息**不會取消**同頻道正在等的判斷（去抖動）。例如有人先問她一句，下一秒別人 @ 朋友講別的，前一句的判斷照樣進行。

## 注意模式判斷的細節（`bot._attention_gate`）
- 進判斷的條件：在注意時間內、不是雜訊、說話的人不在洗版冷卻、沒被程式端擋下。
- 要判斷之前依序檢查：
  1. 有沒有更新的一則（或有人直接叫了她）→ `skipped:superseded`
  2. 頻道是不是靜音中 → `skipped:muted`
  3. 注意時間還在不在 → `skipped:attention_ended`
  4. LLM 忙 → 等它空，等過會記 `waited_llm: true`；超過 20 秒 → `skipped:llm_busy_timeout`，log 也記一行
- 判斷的追蹤紀錄是 `kind=chime`、`trigger=attention_gate`，`final` 會記：`decision`、`threshold`、`action`（reply／none）、`replied`（有沒有交給回覆排程；熱鬧模式中收集起來的也算 true）。
- 門檻用正式的插話門檻（`CHIME_IN` 等級 1＝0.7，或 `CHIME_THRESHOLD`）。
- 去抖動用 `CHIME_DEBOUNCE_SEC`（預設 4 秒），所以主伺服器的注意模式接話會比以前**慢約 4 秒再加判斷時間（約 0.5 秒）**。

## 沒把握的地方
1. **「被叫閉嘴本來就不回」跟現況不符**（規格要我確認現況）：
   - 直接叫她又叫她閉嘴（「Yuki 閉嘴」）會被當成「叫她」。在注意模式內，「閉嘴」是結束字，所以她會回道別（`EXIT_REPLY`）。不在注意模式時，她會照一般流程回一句。
   - 「Yuki 我沒叫你」也算直接叫她（`direct_call` 認得閉嘴類），一樣會回。
   - 這次只改了「注意模式內、沒直接叫她」的情況。直接叫她的這條路沒改，要不要改由 PM 決定。
2. **新題是合成的、語氣很明顯**。真實對話裡，接她的話跟跟朋友講話混在一起時，正確率可能比較低。另外，「繼續跟她講」9 題全靠模型判斷，沒有被程式端擋錯的機會，所以先擋那條「會不會擋到真的在跟她講的話」只有單元測試覆蓋，沒有題目量過。
3. **句首是其他 bot 名字的評論也會被擋**（例如「Nova 好笨」，沒提到她）。這類話本來就不是跟她講，應該沒差。但如果別的 bot 的名字是常見的詞（例如 bot 叫「Music」），日常句子開頭剛好是這個詞也會被擋。
4. **注意模式內 LLM 忙時，最多等 20 秒**。這段時間內，同頻道有新的一則（不是被擋、也不是雜訊），舊的就放棄。所以大家連續講的時候，她只判斷最後一則，跟插話的去抖動一樣。如果最後一則剛好是雜訊或 @ 別人，前面那則還是會判斷。
5. 主伺服器的追蹤紀錄會多很多 `chime` 筆數：注意時間內每句一筆，被先擋的也寫。
6. 沒有在 Discord 上實測（規格沒要求，而且不能停或重開 Yuki）。上線前 Yuki 要重開，新程式才會生效。
