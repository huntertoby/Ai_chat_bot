# D-22 報告：插話判斷改用模型機率＋門檻

## 結論
機制做好了（logprobs 算開口機率、門檻可調、拿不到自動退回），但**正確率沒有提升**：最好 78%，跟現在一樣，離 85% 差 7 點。
所以 `CHIME_USE_LOGPROBS` **預設關**（效果相同、慢約 0.07 秒）。要開的話建議 `CHIME_PROB_THRESHOLD=0.6`。

## logprobs 可行性
- 可行。關掉思考時 `/v1/chat/completions` 回每個輸出 token 的前 5 名機率；JSON schema 限制**不影響**這個分布（有、無 schema 輸出的 token 和機率完全一樣）。
- `action` 的值（reply／react／none）各自是**單一 token**，位置用「輸出文字裡 `"action": "` 之後的第一個 token」找（不依賴欄位順序）。機率 = reply ÷（reply＋react＋none）。
- 現行欄位順序是 reason、kind、action…：action 前面已經寫了 reason 和 kind，所以機率幾乎是 0 或 1（50 題裡 33 題 ≥0.9，17 題 =0），門檻掃了沒差別。
- 實驗：把 action 放最前面（`--action-first`），機率才有分布，但門檻要降到 0.15～0.2 才有 82%（0.5～0.8 反而 58～76%）。0.15～0.2 不在規格的掃描範圍、又是在同一份 50 題上挑的，過擬合風險大，**沒採用**。
- 拿不到 logprobs、找不到 action 位置時退回模型寫的 `participate`，追蹤紀錄有 `prob_source`（`logprob`／`participate`）、機率、門檻。

## 門檻掃描（chime 50 題，temperature 0 所以兩次結果相同；機率記下後離線套門檻）
現行欄位順序＋logprobs（兩次一樣）：

| 門檻 | 總正確率 | talk_to_me | about_me | others | 代名詞 | 誤插／漏插 |
|---|---|---|---|---|---|---|
| 0.5 | 78% | 100 | 58.8 | 75 | 9/9 | 7／4 |
| **0.6** | **78%** | 100 | 58.8 | 75 | 9/9 | 7／4 |
| 0.7 | 76% | 94.1 | 58.8 | 75 | 9/9 | 7／5 |
| 0.8 | 72% | 82.4 | 58.8 | 75 | 8/9 | 7／7 |

- 對照（不用 logprobs，模型寫的 participate，門檻 0.7）：78%（100／58.8／75，代名詞 9/9）。
- 實驗 action 放最前面：0.5／0.6／0.7／0.8 = 76／74／76／58%。
- 預設選 **0.6**（0.5、0.6 並列最高，取較安靜的）。里程碑 20／轉貼 20（跑 1 次）：各門檻都是 **100%／0%**，沒退步。

## 兩條規則變體
1. 「有人接著她剛講的話說下去，即使很短，算在跟她講話」：現行規則已有「接你剛講的話（包括很短的接話）」，**不用加**，沒跑。
2. 「兩人一來一往解釋事情、話沒講完，不要插話」（`--variant explain_flow`，只加一行描述、無範例句）：跑 2 次，78% → **76%**（about_me 58.8 → 52.9，誤插 7 → 8），代名詞 9/9、里程碑 100%／轉貼 0% 沒變。沒到 +3 點，**不採用**（變差 2 點）。

## 速度（中位數／P90）
- 不用 logprobs：0.578／0.690 秒（符合 ≤0.6）。
- 用 logprobs：0.648～0.727／0.77～0.86 秒（慢約 0.07～0.15 秒；回傳每個 token 的機率要多算多傳）。里程碑 40 題 0.656／0.815（有圖 0.813）。action 放最前面更慢（0.77～0.81）。
- 評估時 Yuki 沒有在跑（log 最後一筆是前一晚），LM Studio 只有評估在用。

## 距離 85% 還差多少、錯在哪
最好 78%，差 7 點（約 3.5 題）。錯的 11 題（門檻 0.6）：
- 誤插 7 題：6 題 about_me（別人在講她、但不是在跟她說話，模型給 about_me 且機率 0.91～1.00）、1 題 others（也被判 about_me）。這是模型分類本身的錯，確定性很高，調門檻救不了。
- 漏插 4 題：1 題 about_me（接她的話，模型給 other、機率 0）、3 題 others 的 `has_material`（有料可補）機率 0。
- 要再提升得改「別人在講她但不是對她說」那條規則的判斷方式（例如 few-shot 以外的做法、或拆成兩步判斷），不是門檻問題。
