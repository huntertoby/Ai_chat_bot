# R2 報告：回覆 prompt 三個問題（開頭重複、被嘴接不好、人稱搞錯）＋ D-36 髒話

## 結論
- 三個問題的原因都找到了。主要是**程式給模型的內容**少了資訊，不只是 prompt 寫法：
  - 同一個人連續講的幾句會黏成一則送進去，沒標出哪一句才是要回的。
  - 她自己前幾則的回覆照原樣放回對話紀錄，模型會越學越像。
  - @ 到的人在文字裡雖然有換成名字，但沒有任何地方說「這是第三者」。
- 做法：
  - 程式在**最新一則訊息後面**附一段括號提示，內容都是程式算出來的事實：要接的是最後一則（幾句黏在一起時才附）、@ 到的人是第三者、她最近 4 則回覆的開頭、能不能講髒話。
  - 人設補四條規則，都沒有範例句：不用每句叫名字、開頭要變化；被嘴就針對那句回、不轉話題；@名字是第三者；髒話只跟著講（D-36）。
  - 「閒聊不用查」的清單加上「被嘴被嗆」。
- 小評估（改前、改後各跑兩次，人工也逐則看過）：
  - **開頭重複**：連續重複 3／3 → 1／1（32 個接續裡）；「髒話＋名字」開頭 2／2 → 0／0（40 則裡）。
  - **被嘴**：有去查的 3／4 → 2／2（7 題裡）。人工判「有直接回嘴」3／3 → 4／3，進步不明顯。
  - **人稱**：人工判對 4／7 → 8／7（8 題裡）。照實況改寫的兩題 1／4 → 3／4。
  - **D-36**：最近 5 則別人都沒講髒話時，回覆出現髒話 4／3 → 1／1（各 60 則）。專門出的 7 題「乾淨」情境，改前改後都是 0。
- **副作用（要 PM 看）**：改後約 1～3% 的回覆壞掉，改前是 0。壞掉的樣子有兩種：
  - 把規則講出來，像在自言自語規劃怎麼回。
  - 照抄對方那幾句。
  - 每一版放法都有（放 system 也有），見「沒把握的地方」第 1 點。
- 回覆評估重跑（各兩次）：
  - 合成 200、真實 80、閒聊 30、回覆用表情都沒退步。合成和真實是跟同時段的對照組比，對照組本身就比 R1 低。
  - **兩岸題可能退步**：現在 61%（4 次），同時段對照組 73%，R1 80%。原因沒能確定，見「回覆評估」。
- pytest：**443 passed**（結束碼 0）。check_private 通過（結束碼 0）。沒有 push。

## 原因（看 11/19 實況追蹤紀錄 15 則回覆 ＋ 程式）
### 1. 開頭千篇一律（連續 5 則「髒話＋名字」開頭）
- 人設寫「可以講髒話」「叫人用對話紀錄裡的名字」，群組氛圍那段又強調「髒話、互嘴是日常」。模型把這讀成「每句都可以用髒話起頭、每句都叫名字」。
- `to_messages` 把她自己前面的回覆當成 assistant 訊息放回去。實況第一次出現「幹 某人 …」之後，後面幾則回覆前面都已經有兩三則同樣開頭，模型照著自己的格式接下去。
- 程式和人設都沒有任何東西提醒她「自己最近怎麼開頭」。

### 2. 被嘴接不好（回頭講對方更早說的事、查了 3 次）
- 同一個人連續 5 句（一個沒聽過的詞、兩句當兵的事、一句閒聊、最後一句嘴她）被 `to_messages` 合成**一則** user 訊息。沒有標記哪一句是這次要回的。
  - `Brain.reply` 收到的 `text`（觸發的那句）沒有用到。
- 那個沒聽過的詞觸發 `BACKGROUND_RULES` 的「對話裡出現你不熟的人事物，先查再接話」。實況查了 `search_chat` 2 次、`read_chat` 1 次，把查詢次數用完（`tool_budget`）。
- 人設只有「被嗆就笑著接、自嘲，或輕輕回一句」，沒說要**針對那句**回。R1 加的「閒聊不用查」清單也沒有包含被嘴。

### 3. 人稱搞錯（「你可以把 @某人 當狗使喚」）
- @ 有換成名字：`message.clean_content` 會把 `<@ID>` 換成「@顯示名稱」。實況送進模型的就是「@名字」，這點沒問題。
- 但規則只講「跟你講話的人說的『你』就是你」，沒講 @ 到的人是第三者。
- 實況前文一直在講另一隻機器人（用「她」稱呼）。最後兩句「因為他是你的奴隸」「你可以把 @某人 當狗使喚」黏成一則送進去，模型把「他」和前文的「她」混在一起，回成「下次要她幹嘛…」。
- 被 @ 的剛好是 owner。`OWNER_RULES` 說她會照 owner 的話做，「把他當狗使喚」跟這條衝突，可能讓模型更傾向轉去講另一隻機器人。這點是推測，沒有單獨驗證。

### 補充：D-36 髒話
- 人設原本直接寫「可以講髒話」，沒有條件。11/19 實況裡，對方沒講髒話她也用「幹」開頭。

## D-36：髒話只在別人先講時才講
- **判斷範圍：最近 5 則別人的訊息**。她自己的訊息不算、也不佔名額，包含她正在回的那則。由程式判斷，不交給模型。
- 詞表在 `yuki/brain.py` 的 `SWEAR`，是常見的台灣髒話：幹、靠北、靠腰、靠杯、媽的、他媽、你媽、三小、北七、白癡／白痴、智障、雞掰／機掰／雞巴／機歪、操你／操妳／操他／操機、淦、去死。
  - 「幹」不算：幹嘛、幹麼、幹啥、幹什麼、幹部、幹活、幹勁、幹練、幹架、幹話、幹事，以及前面是能、樹、苦、骨、才、主、實、精的。
  - 「操」只算「操你」這類，操場、體操、操作不算。
- 有人講 → 提示「最近有人講髒話，你可以跟著講，但不一定要」；都沒有 → 提示「最近大家都沒講髒話，這次不要講髒話」。
  - 平常附在最新一則後面。只有這一句、沒有其他提示時，放 system 最後（見上面「提示放哪裡」）。
- 人設那條改成「髒話：別人先講才跟著講，自己不主動帶。接幹話、開玩笑可以，但出發點是一起玩，不是攻擊人」。沒有範例句。

## 沒把握的地方
1. **約 1～3% 的回覆壞掉**（改前 0／136，改後各版本 0～3／68）。兩種樣子：
   - 把規則或提示講出來，像在規劃怎麼回。例如「我陪他罵、接住那句廢物就好，不講髒話」「這是單純閒聊求助，我直接接話給點建議就好」。
   - 照抄對方黏在一起的那幾句。
   - 放 system 的版本也有，所以不只是括號提示造成的；人設新加的規則字眼（回嘴、不用查、一兩句）也會被講出來。
   - 被嘴類最常出現（7 題裡偶爾 1 題）。正式環境大約每 50 則回覆 1 則，會在群組裡很明顯。
   - 可能的處理：程式擋掉含「回嘴」「接住」「不講髒話」「這次回覆」等字的回覆再重試一次，或把人設那幾條改寫成比較不像指令的說法。這次沒做（超出規格），列給 PM。
2. 被嘴、人稱各只有 7～8 題，兩次之間差 1～2 題，改前改後的差距大多在浮動內。比較確定的只有：開頭重複、被嘴時亂查、乾淨情境講髒話，這三項有下降。
3. 正式環境大部分回覆都會帶提示（她前面講過話就有「最近開頭」那條）。但合成 200、真實 80、兩岸都是**單句提問**，只會看到 system 最後的髒話那句，所以這幾組量不到「提示接在最新一則後面」對查資料的影響。小評估裡有查的題目沒有變差，但題目不多。
4. 「@名字」只認文字裡真的有「@」的名字。Discord 回覆別人時自動 tag 的不算，因為文字裡沒有 @。另外名字裡有空白的話，從文字抓會被截斷（mentions 有給時用 mentions 的完整名字，沒問題）。
5. 「最近開頭」取前 6 個字。名字很長時，會只看到「幹 某某某」的一部分；看起來還是有效（A7、A8 都沒再出現），但沒有專門測。
6. 實況人稱錯的另一個可能原因（`OWNER_RULES` 說她會照 owner 的話做，跟「把 owner 當狗」衝突）沒有單獨驗證，也沒改 `OWNER_RULES`。
7. 兩岸題 61% vs 對照組 73%：評分員不穩、樣本小，拆不出是哪一條，見「回覆評估」。
