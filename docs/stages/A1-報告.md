# A1 開機自動啟動 — 報告（2026-11-18）

## 結果
腳本做好、手動測試通過；**捷徑還沒放進啟動資料夾**（開發 PM 執行 `install.ps1` 時被權限擋下，要使用者自己跑一次），所以「重開機後自動開」還沒驗。

## 做了什麼
- `scripts/autostart/`：
  - `watch_yuki.ps1`、`watch_breezy.ps1`：各自啟動並看顧；掛掉 10 秒重開，1 小時超過 5 次就停並寫 log。BreezyVoice 先等 WSL（最多 3 分鐘）。已有人開著（含使用者手動開的）就不重開。
  - `start.ps1`（經 `launch.vbs` 隱藏視窗開兩個看顧）、`stop.ps1`（只結束 `logs/autostart/*.pid` 記的程序）。
  - `install.ps1`／`uninstall.ps1`：在目前使用者的啟動資料夾建立／刪除 `Yuki 自動啟動.lnk`，不動其他系統設定。
  - `common.ps1`：共用函式（規格沒列，實作者加的）。
- `README.md` 加「開機自動啟動」一節；`CLAUDE.md` 環境節加一行（開發時先 stop、測完 start）。
- 判斷「Yuki 已在跑」比對本專案完整路徑，不會誤認同一台電腦的其他 `main.py`（例：power_tracker）。

## 已知限制
- 啟動資料夾要**登入 Windows 後**才會跑。
- LM Studio、SearXNG 不包含在內；沒開的話 Yuki 上線但不會回話。
- BreezyVoice 看顧每次啟動前會在 WSL 裡 `pkill -f breezy_server.py`（清掉自己上一輪的殘留）。若使用者剛好手動開了一個、還在載模型（約 20 秒內），會被清掉。
- 開機自動開的 Yuki 在跑時又手動開一個，會變兩個 Yuki；`CLAUDE.md` 已寫要先 `stop.ps1`。

## 使用者要做的
1. 在專案資料夾跑一次：
   `powershell -ExecutionPolicy Bypass -File scripts\autostart\install.ps1`
2. 重開機、登入，等 2～3 分鐘，到測試伺服器 `/來語音` 聽是不是 BreezyVoice 的聲音。
3. 回答：開機會自動登入嗎？LM Studio、SearXNG 會自己開嗎？
