# R3 修回覆壞掉＋確認兩岸題 — 規格

> 來源：`docs/stages/R2-報告.md`「沒把握的地方」第 1、2 點。總 PM：R2 先不上線（正式環境維持 D-34 版，commit a7741e0 的程式），R3 修完才上線。詞表照保守算法，「白癡、智障、去死」算髒話（不用問使用者）。

## 要做的
1. **回覆壞掉要回到 0（或接近 0）**：R2 改後約 1～3% 的回覆：
   - 把「這次回覆」提示裡的規則講出來（像在規劃怎麼回，例如提到要接哪句、不講髒話、換開頭）；
   - 照抄對方那幾句。
   - **用程式檢查，不要只靠 prompt 叫它別講**。例如：回覆出來後程式比對——跟提示的字句（或提示裡的關鍵片語）重疊太多、跟最新幾則別人的訊息重疊太多 → 判壞掉，重生一次（有上限，例如 1 次；還是壞就用比較保守的做法，例如不附提示再生一次，或不回，選一個並在報告說明理由）。檢查要寫成獨立函式並有單元測試，門檻放常數，誤判（正常回覆被擋）也要量。
   - 也可以同時調整提示的寫法讓它比較不會被講出來（例如提示的位置、格式），但程式檢查一定要有。
   - 重生會多花時間：報告寫觸發比例和多花的秒數。
2. **兩岸題確認**：
   - R2 版（現在 main）和 D-34 版（a7741e0 的 prompt／組法，當對照）**各跑 4 次以上**，同一時段交錯跑，報每次分數、平均、範圍。
   - 差距超過兩邊各自的浮動才算真的退步。真的退步就找原因修好，目標回到對照組水準（不低於對照平均減一次浮動）。
   - 髒話那兩條（D-36）**不能拿掉**，可以改寫法或位置（例如單句提問時的放法）。
   - 評分員不穩的話，報告附人工看過的錯題（是不是真的立場有問題，還是評分員誤判）。
3. 詞表：「白癡、智障、去死」維持算髒話，不改。

## 評估（改完後，各兩次，D-21）
- R2 小評估（`data/eval_r2/`）：壞掉比例（必報，兩次都要是 0 或接近 0）、開頭重複、人稱、被嘴、D-36 髒話比例——不能比 R2 改後明顯變差。
- 回覆評估：合成 200、真實 80、閒聊 30、回覆用表情、兩岸（兩岸照第 2 項跑 4 次以上）。跟同時段對照組比。
- 報告附幾則被程式檢查擋下、重生後的回覆（名字佔位）。
