# B1 看圖片 — 報告（2026-11-18）

## 結果：✅ 完成
被叫到時看得懂圖。測試伺服器實測：單張迷因看懂、兩張圖分得出來、YouTube 連結照常回。

## 做了什麼
- `yuki/vision.py`（新）：只取 Discord CDN（`cdn.discordapp.com`、`media.discordapp.net`）的圖片附件和 embed 圖；下載逾時 5 秒、上限 10MB、縮到長邊 1280、轉 JPEG；失敗就少那張，不讓回覆失敗。圖片只在記憶體，不存檔。
- 回覆時從最近 10 則挑圖，最多 5 張、最新優先，附在最後一則 user message，每張標「誰貼的、那則寫什麼」。語音回覆不帶圖。
- 只貼圖沒打字的訊息也進對話紀錄（文字記成「（貼了圖片）」），所以「貼圖＋@Yuki」會直接看圖回。
- 追蹤紀錄：圖片換成 `[圖片]`，另記 `images`（張數）和來源訊息 ID，沒有 base64。
- prompt：只有真的附圖時才加一句說明（沒圖時 prompt 不變，不影響評估基準）。
- `glance_images()`（長邊 512、最多 3 張）先做好給 B2 插話判斷用。
- 新設定：`VISION_ENABLED`、`VISION_REPLY_LONG_SIDE`、`VISION_GLANCE_LONG_SIDE`、`VISION_MAX_IMAGES`、`VISION_RECENT_LINES`、`VISION_MAX_MB`。
- 顯存：現在的模型已帶視覺模組，不用換模型、不多吃顯存。長邊 512／1024／1600 約 215／790／1900 token。

## 實測中修的兩個 bug
1. **圖沒送進模型**（22:34 第一次實測）：brain 呼叫 `vision.collect` 傳了它不收的參數，被「取圖失敗只用文字」接住 → 0 張圖，她靠搜尋結果亂猜。修好並補了一個走 brain 那層的測試（原本的測試只測 vision 本身）。commit f6bb056。
2. **@Yuki 沒反應**（23:27）：輸入框選到的「@Yuki」是 Discord 幫 bot 建的身分組，不是 bot 本人，原本只認 bot 本人 → 安靜略過。改成 bot 自己的身分組被 @ 也算叫她。
